# Google Searchのランキング変数

最終レビュー: 2026-08-26

## 目的

本書は、`web piano`、`browser piano`、`online piano`、`virtual piano`で長期的な可視性を目指す際に重要なランキング変数・システムを記録する。根拠は、Google Searchドキュメント、米国Google独禁法訴訟の宣誓証言・証拠、2024年Google Content Warehouse APIドキュメント流出と慎重な技術分析、SearchPilot・Ahrefs・SISTRIXの統制テストおよび大規模観察研究である。

Googleの完全な式やシグナルの重みが公開されているとは扱わない。内部スキーマのフィールド存在は、現在の本番ランキング経路での有効利用を証明せず、相関研究も因果を証明しない。

## 要約

Googleランキングは単一のチェックリストではなく、次のパイプラインとして捉える方がよい。

```text
クロール・インデックスの適格性
  -> クエリ理解・候補取得
  -> 関連性・品質スコアリング
  -> リンク・権威性・インタラクション由来シグナル
  -> コンテキスト固有の再ランキング
  -> スパム・多様性・SERP機能による調整
  -> 国・言語・デバイス・時点に応じた最終結果
```

逐語的な数式ではないが、有用なモデルは以下である。

```text
順位(クエリ, 文書, コンテキスト, 時点)
  ~= 適格性ゲート
     * f(意図との一致,
         文書品質,
         サイト品質,
         権威性,
         過去のクエリ・文書満足度,
         ページエクスペリエンス,
         鮮度ニーズ,
         ロケール・デバイス)
     - スパム・降格システム
```

webpianoの持続的な優位性はSEOテキストの量ではない。検索結果から高速で分かりやすいキーボード中心の楽器に直接到達でき、演奏者に再訪・共有・リンクする理由を与えることにある。

## 根拠の等級

| 等級 | 意味                                                 | 導ける結論                                                                                               |
| ---- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| A    | 現行Googleドキュメントまたは宣誓・裁判証拠で確認済み | 記載範囲でシステムまたは入力は存在する。重みは不明                                                       |
| B    | 2024年流出APIスキーマまたは内部ドキュメントに存在    | フィールドは存在または保存されていた。本番利用と重みは不明の場合がある                                   |
| C    | 統制SEOスプリットテストまたは小規模介入研究          | テスト対象サイトのオーガニックトラフィックを生んだ、またはおそらく生んだ。他サイトへの転用は保証されない |
| D    | 大規模観察相関                                       | 変数が共に動く。逆因果・交絡があり得る                                                                   |
| U    | 未確認、間接的、または誤解されがちなもの             | 直接ランキング要因として説明しない                                                                       |

SearchPilotは通常、順位とSERPクリック率効果を合わせたオーガニックトラフィックを測定し、Google内部スコアは開示しない。複数等級がある行では、各出典が裏付ける層だけを主張する。たとえば`A`と`B`を組み合わせても、流出フィールドが本番利用で確認済みになるわけではない。

## 現在のwebpianoのベースライン

レビュー時点のローカルアプリケーションには次の基盤がある。

- `/`はマーケティング用ランディングページでなく演奏可能な楽器を直接レンダリングする。
- title、description、canonical URL、Open Graphメタデータ、PWA manifest、viewportは`src/constants/metadata.ts`と`src/app/layout.tsx`で設定される。
- 楽器は37個の物理キーを32音へ割り当てる標準鍵盤、左右独立レンジ、ポインター／タッチ入力、Spaceキー／手動固定サステイン、スマートフォンペダルに対応する。
- 空のJavaScript shellではなく意味のあるサーバーサイドレンダリングHTMLを返す。

実装には次も含まれる。

- `robots.txt`と`sitemap.xml`用のNext.js metadata routes。
- オフラインフォールバックと一時スマートフォンペダルルートへの明示的`noindex`メタデータ。
- 説明的title・H1・可視タスク説明・事実に忠実な`WebApplication` JSON-LD・ソーシャル画像altメタデータ。
- 簡潔な`public/llms.txt`エージェントディレクトリ。GoogleはGoogle Search・生成AI機能で使用しないと明示している。SEOレバーではなく実験的相互運用性支援である。

残るSEO制約は珍しいアルゴリズムフィールドではない。

- 楽器にレッスン、曲、コード、関連ツールを組み合わせる競合より、インデックス可能コンテンツ面はまだ浅い。
- クエリ、国、デバイス、インデックス状況、フィールド性能、プロダクトのタスク完了を併せて測定する再現可能な方法が必要。
- 新ページ導入時は、クロール可能内部リンク、sitemap網羅、厳格な重複防止ルールが重要。

## このプロダクト向け優先度モデル

### P0: 測定可能で明白なタスク一致を確立する

1. 1位目標を掲げる前に、たとえば`US / English / desktop`のように主市場を定義する。
2. キーワードを詰め込まず、title、H1、ファーストビューで`online piano`、`play in your browser`、`computer keyboard`を明確に表す。
3. 直接演奏を守る。初回発音前にサインアップ壁、広告インタースティシャル、長いチュートリアルを置かない。
4. フィールドLCP、INP、CLS、正常な初回発音までの時間、初回発音成功率、継続演奏セッションを別々に測定する。
5. Search Consoleを接続し、クエリを国・デバイスで分割する。
6. URLセット拡張前に、インデックス可能性、canonicalization、`robots.txt`、sitemapの挙動を検証する。

### P1: 自然にリンク・再訪を得る価値を作る

1. キーボードマップ、演奏可能スケール、コード、最初の曲の練習を公開する。各ページにはSEOコピーだけでなく楽器を含める。
2. 教師、生徒、配信者、Web Audio開発者向けに共有・埋め込み可能なミニピアノと練習リンクを作る。
3. 再現可能な方法論で一次のブラウザ／音声測定・互換性ノートを公開する。
4. 音楽教育、ピアノ学習、ブラウザ音楽、Web Audio、PWAコミュニティから関連する編集的紹介を得る。
5. 内部リンクで明確な`楽器 -> 学習 -> 練習 -> 楽器`ループを作る。

### P2: 表示と副次的適格性をテストする

1. title・description変形をSearch Console CTRとオーガニックセッションでテストする。他業界の勝ち式が転用できるとは前提にしない。
2. 可視コンテンツを正確に表し、有用な検索機能の対象となる構造化データだけを追加する。
3. 可能であればコンテンツの追加・削除を限定コホートでテストする。
4. AI回答、動画などにより順位が安定しても利用可能クリックは変わるため、SERP構成をレビューする。

## 計測契約

Googleの出力とプロダクト成果を分ける。

### Search Consoleの出力

| 次元     | 指標                                                     |
| -------- | -------------------------------------------------------- |
| クエリ   | 表示回数、クリック数、CTR、平均掲載順位                  |
| 国       | 同じ4指標。目標市場を固定                                |
| デバイス | デスクトップ、モバイル、タブレット                       |
| ページ   | クエリからランディングページへの対応・カニバリゼーション |
| 時間     | 週次トレンド、28日間・3か月比較                          |

Search ConsoleのCTRと平均掲載順位はサイトで取得できる測定値である。Google内部NavBoost入力の完全な見取り図として扱ってはならない。

### プロダクト成果

| 成果               | 推奨する定義                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------- |
| 初回発音成功       | 最初のピアノ入力から10秒以内に音が出たセッション ÷ ピアノ入力のあったセッション                       |
| 初回発音までの時間 | 最初のピアノ入力からノート開始まで。デバイス別に中央値・p75を報告                                     |
| 意味のある演奏     | 初期ヒューリスティック: 少なくとも20秒にまたがる12回以上のnote-onイベント。実セッション観察後に見直す |
| サステイン利用     | 意味のある演奏セッション中のSpaceまたはスマートフォンペダル利用                                       |
| 再訪利用           | 同意済み仮名ブラウザが7日または28日以内に別の意味ある演奏セッションを行う                             |
| 共有／参照         | 成功した共有アクション、または帰属可能なreferrerもしくはcampaign parameterを伴う訪問                  |
| リンク獲得         | 新規の関連する編集的参照ドメイン・遷移先ページ                                                        |

これらはプロダクト・配信指標である。直接Googleランキング入力が証明されない場合も価値がある。

## レビュールール

更新時は以下を守る。

1. 確認済みシステム、流出フィールド、実験、相関、裏付けのない主張を区別する。
2. 根拠等級を変える前に、出典の日付・スコープを追加する。
3. 本番利用根拠なしに、保存されたフィールドを有効なランキング要因と主張しない。
4. 一つのSearchPilotクライアント結果を普遍的割合に一般化しない。
5. 少なくとも6か月ごとに裁判リンク、Googleドキュメント、Core Web Vital定義、スパムポリシーを再確認する。
6. クエリ優先度を決める前に、目標国・言語・デバイスごとにライブSERPを別途再確認する。
